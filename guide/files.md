# 文件与手动编辑

[返回首页](../README.md)

记忆就是文件：磁盘上的 Markdown 是唯一真相，插件不在内存里另存一份。你用编辑器新建、修改、删除文件，下一次工具调用和新会话注入立即反映，不用重启。

```text
<memoryRoot>/
  global/                    # 全局记忆（跨项目共享）
    <name 的 slug>.md         # 一条记忆一个文件（YAML Frontmatter + 正文）
    MEMORY.md                # 生成的总览：按主题列出说明和条数，手改会被覆盖
    _index/                  # 主题索引，可以手改
      index.md               # 入口：有哪些主题、每个主题的说明
      topics/<主题>.md        # 一个主题一页，列出这个主题下的记忆
      topics/_unsorted.md    # 「未整理」：还没归到主题里的记忆
    .archive/                # 已遗忘、已取代的记忆；遗忘 14 天后自动清理
    .history/<记忆 id>/       # 历史版本：状态变了的记忆，变化前的整条内容；随记忆提升、移动，彻底删除时一起删
  <项目slug>-<hash>/         # 项目记忆（按工作区隔离）
    .workspace               # 一行：该项目的本地绝对路径
    <name 的 slug>.md
    MEMORY.md
    _index/
    .archive/
    .history/
  .state/                    # 插件自用：快照、待决事项、扫描缓存、召回统计、体检设置与记录等
```

备份或换机时复制整个 `<memoryRoot>`，包括隐藏的 `.archive/`、`.history/` 和 `.state/`：撤销快照、待决事项、忽略记录都在 `.state/` 里，没法从记忆文件重建。

全局记忆由你确认提升后才进 `global/`：模型要新建全局记忆时，记忆先落在当前项目、标为提升候选。

主题页里每条记忆一行，链接到记忆文件，模型拿到就能直接读原文；`.archive/` 是隐藏目录，DeepSeek Harness 的 grep 工具搜不到里面已遗忘的内容。



## 手动编辑规范

- **新建**：一个 `.md` 文件，Frontmatter 最少只要 `name` 和 `type`，正文就是记忆内容。`id`、时间戳、`tags`、`summary`、`confidence` 都可以省，插件在下一次写入或会话启动时补齐。
- **事实时间**：`factTime` 记录这件事发生或成立的时间，不影响带入和检索。
- **时间戳**：接受 `2026-09-01`、`2026-09-01T08:30:00Z`、带时区偏移等常见写法；缺省取文件修改时间。
- **修改**：改完下次读取就生效，更新时间按文件修改时间刷新。手改过的记忆和其他记忆一样，对话里需要时模型可以照常更新。
- **过期**：文件里的有效期 `validFrom` / `validTo` 是本机时间，如 `2026-11-05 18:00`，手改照这个写；只写日期时取文件修改时间的时分。`validFrom` 控制生效时间，到点前不带入新对话，也搜不到。旧版本写的 UTC 时间在下一次写入或会话启动时自动改成这种写法。`validTo` 已过的记忆留在原位，不注入、不检索；`memory_health` 计入过期条数，`memory_scan` 逐条列出并建议延长有效期或遗忘。
- **恢复**：误删的记忆在 `.archive/` 里，用 `memory_snapshot` 恢复，或把文件搬回上一层并把 `status` 改成 `active`。
- **格式错误**：解析不了的文件单独隔离，不影响其他记忆；`memory_scan` 列出文件路径和报错，`memory_health` 计入条数，修好即生效。
- **主题索引**：`_index/` 下的文件可以手改，调行的顺序、改主题说明、把一行挪到另一个主题页都留得住。新会话载入记忆时会核对一遍：漏掉的记忆补进「未整理」，指向已不存在的记忆的行去掉，行里的名称和摘要跟着记忆更新。
- `MEMORY.md` 是从主题索引生成的，不要手改。已过期的记忆仍在索引里列着，归档或删除后才去掉。
